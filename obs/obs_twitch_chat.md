Чат Twitch на сценах OBS: свой виджет `~/develop/obs-twitch-chat/chat.html` вместо
хостящегося KapChat. Продолжение [[obs_setup]], коллекция сцен «Стрим», три источника
чата. Оформление (пользовательский CSS источников) при переезде не менялось.

Причина замены — чат замирал при отключении VPN. Блокировки тут почти ни при чем:
без туннеля напрямую доступны и страница виджета, и сам Twitch IRC.

## Почему KapChat замирал

Когда из-под системы уходит VPN-интерфейс, TCP-соединение не получает RST: маршрут
исчез, отправлять некому. Сокет остается в состоянии `ESTAB` с адресом мертвого
туннеля, данные не идут, но и ошибки нет. Замер на живом OBS до переезда:

```
== ДО ==            ESTAB 10.71.43.29:57392 -> 44.225.114.193:443  (x3)
== VPN OFF, +75s == ESTAB 10.71.43.29:57392 -> 44.225.114.193:443  (x3)
```

Для браузера соединение выглядит живым, поэтому `reconnecting-websocket` внутри
KapChat не срабатывает — переподключаться, с его точки зрения, не от чего. Чат висит
до TCP-таймаута ядра, а это часы. Ручной обходной путь был один: правый клик по
источнику → «Обновить», тогда CEF открывает сокеты заново.

Вторая слабость KapChat: перед подключением к чату он синхронно ходил за бейджами
на свой `bootstrap`-API, и неудача этого запроса означала, что сообщения не пойдут
вовсе.

## Что провайдер отдает без VPN

Проверено 09.09.2026 отключением туннеля:

| Хост | Зачем | Без VPN |
| --- | --- | --- |
| `irc-ws.chat.twitch.tv` | сам чат (WebSocket) | работает |
| `static-cdn.jtvnw.net` | эмоуты и бейджи Twitch | работает |
| `nightdev.com` | bootstrap-API с бейджами | работает |
| `cdn.jsdelivr.net` | картинки twemoji | работает |
| `cdn.betterttv.net` | эмоуты BTTV | **блокируется** |
| `cdn.frankerfacez.com` | эмоуты FFZ | **блокируется** |

У заблокированных DNS подменяется на заглушку `188.186.154.79`, а при обращении по
правильному IP приходит RST — то есть режется и по SNI. Проверка руками:

```
getent ahostsv4 cdn.betterttv.net
curl -s -o /dev/null -m 8 -w "%{http_code} %{errormsg}\n" https://cdn.betterttv.net/
```

Раз BTTV и FFZ без туннеля не работали и раньше, из виджета они выкинуты совсем.

## Как подключено

Три браузер-источника, у всех один файл и разные параметры:

```
Chat · Затухающий  file:///home/kkulebaev/develop/obs-twitch-chat/chat.html?channel=tinkerdev&fade=true&bot_activity=true&prevent_clipping=false
Chat · Постоянный  file:///home/kkulebaev/develop/obs-twitch-chat/chat.html?channel=tinkerdev&fade=false&bot_activity=true&prevent_clipping=false
Chat · Крупный     file:///home/kkulebaev/develop/obs-twitch-chat/chat.html?channel=tinkerdev&fade=true&bot_activity=true&prevent_clipping=false
```

Галочку «Локальный файл» **не включать**: OBS тогда собирает URL из пути сам и все
параметры после `?` теряются. Адрес вставляется в обычное поле URL, схема `file://`
CEF принимает.

Параметры те же, что были у KapChat: `fade=true` — строка живет 30 секунд, `fade=false`
— не удаляется вовсе (потолок 100 строк), `bot_activity=true` — не прятать сообщения
ботов и команды на `!`.

Рядом с `chat.html` лежат `twemoji.min.js` (локальная копия, чтобы страница не зависела
от чужого CDN на старте) и `badges.js` — снимок бейджей Twitch на 366 типов.

## Разметка и CSS

Разметка строки и базовые стили скопированы у KapChat дословно, поэтому весь
пользовательский CSS источников работает без единой правки — все тонкости из раздела
«Уже настроено» в [[obs_setup]] остаются в силе:

```
.chat_line[data-nick][data-id][data-timestamp]
  ├─ .time_stamp        скрыт базовым стилем
  ├─ .badges > img.tag  бейджи
  ├─ .nick              цвет из тега color
  ├─ .colon             двоеточие после ника
  └─ .message           текст, .emoticon и .emoji внутри
```

Служебные строки по-прежнему помечены `data-nick="Chat"`, так что правило
`.chat_line[data-nick="Chat"] { display: none }` продолжает их прятать.

Мелочи, которые пришлось воспроизвести один в один, иначе поехала бы верстка:
`body { margin: 5px }`, `#chat_box { position: absolute; width: calc(100% - 10px) }`,
`.tag { height: 18px; vertical-align: bottom }`, `.emoticon { margin-bottom: -7px }`.
Цвет ника без тега `color` берется из палитры Twitch по коду первой буквы ника
(`defaultColors[nick.charCodeAt(0) % 15]`) — то же, что делал KapChat.

Индексы эмоутов в теге `emotes` считаются в кодовых точках, а не в UTF-16, поэтому
разбор идет через `Array.from`: иначе одна елочка в начале сообщения сдвигает всю
разметку на символ.

## Переподключение

Главное отличие от KapChat: живость проверяется не событиями сокета, а тем, отвечает
ли собеседник.

- PING уходит после 15 секунд тишины (любой входящий байт таймер сбрасывает, поэтому
  на активном чате служебного трафика почти нет);
- нет PONG за 7 секунд — сокет считается мертвым;
- обработчики снимаются до `close()`: на зависшем сокете `onclose` может не прийти
  вовсе, и переподключение не должно этого ждать;
- новая попытка через 2 секунды, дальше с удвоением до 15 секунд, счетчик сбрасывается
  на команде `001` от сервера.

Итого простой не больше 24 секунд. Замер на живом OBS, отключение туннеля в 11:52:57:

```
  +10с: через туннель 3, напрямую 0
  +20с: через туннель 3, напрямую 2
  +30с: через туннель 3, напрямую 3   <- все три источника переехали
```

Обратное включение VPN отрабатывает так же. Брошенные сокеты какое-то время висят
в `ESTAB` (FIN некуда отправить), пока их не уберет ядро — это нормально, не утечка.

Дополнительно виджет переподключается по событию `online` и по команде `RECONNECT`,
которую Twitch присылает перед своими перезагрузками.

## Бейджи

Берутся с `https://nightdev.com/api/1/kapchat/channels/tinkerdev/bootstrap` — это
открытый эндпоинт KapChat, который отдает `Access-Control-Allow-Origin: null`, поэтому
запрос проходит даже со страницы, открытой как `file://` (origin у нее `null`).

Запрос фоновый и на подключение к чату не влияет: пока он идет, работает снимок из
`badges.js`, а если API не ответит — снимок так и останется рабочим набором. Бейдж,
версии которого в наборе нет, просто не рисуется: пустая картинка в кадре выглядит
как дыра в строке.

Обновить снимок, если появятся новые бейджи канала:

```
curl -s https://nightdev.com/api/1/kapchat/channels/tinkerdev/bootstrap \
  | python3 -c 'import json,sys; d=json.load(sys.stdin); print("window.BADGES_SNAPSHOT =", json.dumps(d["badges"], ensure_ascii=False, separators=(",",":")) + ";")' \
  > ~/develop/obs-twitch-chat/badges.js
```

## Чего нет по сравнению с KapChat

- эмоуты BTTV и FFZ — их CDN блокируются провайдером, без VPN не работали и раньше;
- чирмоты (картинки за биты) — биты покажутся текстом вроде `Cheer100`;
- темы оформления (`theme=` в URL) — не нужны, оформление живет в CSS источников.

Сообщения о подписках и рейдах (`USERNOTICE`) не показывает ни KapChat, ни виджет.

## Как проверить, что чат жив

Соединения браузер-источников с Twitch IRC (адреса Twitch раздает разные, поэтому
фильтровать по конкретному IP нельзя — легко решить, что чат отвалился, когда он
просто переехал):

```
ss -tanp | grep obs-browser | grep -vE "95\.181\.|91\.215\.|65\.9\."
```

Должно быть по одному соединению на каждый источник чата в кадре. Чей это адрес,
подтверждает сертификат:

```
openssl s_client -connect <IP>:443 -servername irc-ws.chat.twitch.tv </dev/null 2>/dev/null \
  | openssl x509 -noout -subject
```

Ошибки JS браузер-источников попадают в лог OBS:

```
grep -i "obs-browser" "$(ls -t ~/.config/obs-studio/logs/*.txt | head -1)"
```

Проверять сам файл удобнее в браузере — он открывается по тому же `file://` адресу
и ведет видимый лог служебными строками («Connected.», «Joined channel.»), которые
в OBS скрыты через CSS.
