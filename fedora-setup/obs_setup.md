### Звук приложений отдельно от рабочего стола

Захват окна (`pipewire-screen-capture-source`) звука не несёт, поэтому весь звук в стриме
даёт единственный глобальный «Звук раб. стола» — монитор колонок, куда сваливается всё
подряд: фильм, уведомления, музыка, Discord.

В сам OBS захват звука приложения не вошёл и в обозримом будущем не войдёт:
[PR #6207](https://github.com/obsproject/obs-studio/pull/6207) висит черновиком с 2024 года,
потому что для системного звука нет XDG-портала, а Flatpak-дыру
`--filesystem=xdg-run/pipewire-0` в OBS пускать не хотят. Рабочий способ один — плагин
[obs-pipewire-audio-capture](https://github.com/dimtpap/obs-pipewire-audio-capture).

```bash
curl -LO https://github.com/dimtpap/obs-pipewire-audio-capture/releases/download/1.2.1/linux-pipewire-audio-1.2.1.tar.gz
mkdir -p ~/.config/obs-studio/plugins
tar xzf linux-pipewire-audio-1.2.1.tar.gz -C ~/.config/obs-studio/plugins
```

Плагин объявляет API OBS 28, но с 32.1.1 работает: `obs_open_module` отбраковывает только
модули **новее** себя (`cmp $0x20010001,%eax; ja`), а все требуемые символы есть
в `libobs.so.30`. Жалобы на Fedora 44 в трекере относятся к Flatpak-сборке OBS, у нас RPM.
Русской локали у плагина нет — источники называются по-английски.

После перезапуска OBS на сцену Cinema: + → **Application Audio Capture (PipeWire)** →
приложение-плеер. Плагин поднимает собственный скрытый sink и дублирует в него выходные
порты приложения, поэтому звук продолжает идти в колонки как обычно — ни петли, ни
задержки, ни ручного роутинга при каждом запуске плеера.

Дальше глобальный «Звук раб. стола» надо отключить (Настройки → Аудио → Отключено),
а на Games добавить такой же источник с игрой. Пока он включён, в стрим дважды уходят
алерты: у MemeAlerts/DonationAlerts стоит «Мониторинг и вывод», их вывод идёт в колонки,
монитор которых и захватывает «Звук раб. стола».

- [ ] поставить плагин, перезапустить OBS
- [ ] Cinema: Application Audio Capture → плеер
- [ ] Games: Application Audio Capture → игра
- [ ] отключить глобальный «Звук раб. стола»
- [ ] проверить в записи, что алерты не двоятся

Запасной вариант, если плагин не заведётся, — виртуальное устройство в PipeWire:

```bash
pactl load-module module-null-sink sink_name=Cinema sink_properties=device.description=Cinema
pactl load-module module-loopback source=Cinema.monitor \
  sink=alsa_output.pci-0000_10_00.6.analog-stereo latency_msec=20
```

Плеер переносится в устройство `Cinema` (`pactl move-sink-input <id> Cinema`, удобнее
через `pavucontrol`), а OBS захватывает «Монитор Cinema» обычным источником «Захват
входного аудиопотока». Мониторинг у этого источника оставить **отключённым** — фильм
и так слышно через петлю, иначе будет эхо. Чтобы устройство переживало перезагрузку,
описать его модулем `libpipewire-module-loopback` в `~/.config/pipewire/pipewire.conf.d/`.
Способ рабочий, но требует переносить приложение в устройство руками, поэтому только как
запасной.

### Отдельные аудиодорожки для записи

Сейчас пишется одна сведённая дорожка (простой режим вывода, `RecTracks=1`).
Настройки → Вывод → Режим вывода: **Расширенный** → вкладка «Запись»:

- дорожка 1 — общий микс
- дорожка 2 — только микрофон
- дорожка 3 — только звук приложения (игра / фильм)
- дорожка 4 — только алерты и виджеты

Раскладка источников по дорожкам — в микшере: Options (⋮) → «Расширенные свойства аудио» →
колонки «Дорожки». Сейчас у всех источников проставлены все шесть (`mixers=255`).
При монтаже хайлайтов можно убрать музыку и звук игры, не трогая голос, а из VOD с фильмом —
выкинуть звуковую дорожку целиком. На трансляцию это не влияет: туда уходит одна сведённая
дорожка, номер которой задаётся в Настройки → Вывод → Трансляция.

Разводить по дорожкам имеет смысл после [[#Звук приложений отдельно от рабочего стола]] —
пока весь звук идёт одним «Звуком раб. стола», разделять нечего.

- [ ] переключиться на расширенный режим вывода
- [ ] развести источники по дорожкам

### Битрейт и NVENC

Сейчас: простой режим вывода, nvenc, 6000 kbps, пресет p5, 1920×1080@60.
6000 при 1080p60 для динамичных игр маловато — на движении картинка сыпется.

Варианты:

- снизить разрешение вывода до 1600×900 при тех же 6000 kbps;
- перейти в расширенный режим вывода и включить у NVENC «Психовизуальную настройку»
  и «Предпросмотр» (look-ahead), B-кадры 2 — на Pascal даёт заметно более чистую картинку.

Проверять **только в реальной игре**: Вид → Статистика → «Пропущенные кадры из-за
перегрузки кодирования». 1050 Ti тянет игру и кодирование одновременно на пределе,
на пустом рабочем столе тест ничего не покажет.

- [ ] протестировать под нагрузкой
- [ ] выбрать вариант

## Опционально

### Вебка в 1080p60

Сейчас MJPEG 1280×720@60. На Solo Screen отображается как 1264×711 — практически
пиксель-в-пиксель, мыла нет. 1920×1080@60 (камера поддерживает) дал бы небольшой запас
на суперсэмплинг: чуть меньше шума после уменьшения.

Камера умеет 60 fps только до 1080p включительно, в 4K и 1440p — лишь 30.

При смене разрешения масштаб хранится коэффициентом, поэтому размеры на сценах поедут.
Поправить через `Ctrl+E` → поле «Размер»:

| Сцена | Размер |
| --- | --- |
| Solo Screen | 1264 × 711 |
| Games | 384 × 216 |
| Cinema | 320 × 180 |

### Фиксация баланса белого

Свойства `Cam · Вебка` → элементы управления камерой внизу списка.
Автоэкспозицию при дневном свете разумно оставить, но баланс белого стоит зафиксировать —
иначе кожа плавает между жёлтым и синим. В авторежиме это самое заметное, что портит картинку.

Свет важнее любых настроек: при нехватке света камера задирает усиление, шум давится
MJPEG-сжатием в кашу. Лампа спереди (не сверху и не сзади) даёт прирост, которого не даст OBS.

### Вложенная сцена для оверлея

Три источника алертов продублированы на всех четырёх сценах с разными координатами.
Если унифицировать позиции — можно собрать сцену `Overlay` и вставлять её одним источником:
правка в одном месте вместо четырёх.

## Важно не сломать

- **Не включать** «Выключить источник, когда он не отображается» для алертов — при
  переключении сцены пропустишь донат. Для `Chat` можно.
- Порядок аудиофильтров микрофона: шумоподавление → шлюз → компрессор → ограничитель.
  Шлюз должен резать уже очищенный сигнал, а компрессор — не поднимать шумовой хвост
  между фразами.
- Фильтр резкости у вебки идёт **выше** маски, иначе по скруглённой границе появится ореол.
- Глобальные аудиоустройства (Настройки → Аудио) звучат на всех сценах одновременно.
  Чтобы устройство молчало на конкретной сцене, его надо отключить в глобальных
  и добавить обычным источником на нужные сцены («Добавить существующий» — один источник,
  а не копии: громкость и фильтры общие, звук не рвётся при переходах).

## Уже настроено

- Микрофон вынесен из глобальных устройств: Настройки → Аудио →
  «Микрофон/дополнительный звук» = Отключено, источник `Mic` добавлен на Games / Cinema /
  Solo Screen. На Pause его нет, поэтому на паузе микрофон молчит сам собой.
- Фильтры `Mic`: шумоподавление (RNNoise) → пропускной уровень шума (−35 / −30 дБ,
  атака 25 мс, удержание 200 мс, спад 150 мс) → компрессор (порог −18 дБ, сжатие 4:1,
  атака 6 мс, спад 60 мс, усиление +3…6 дБ) → ограничитель (−1 дБ).
- Вебка переведена на MJPEG 1280×720@60 вместо эмулируемого BGR24 3840×2160@30.
  BGR3 в списке форматов был помечен `(Emulated)` — камера отдаёт MJPEG, а libv4l
  распаковывала его в BGR24 на процессоре (~25 МБ на кадр). CPU в OBS упал с 2.5% до 0.9%.
- Фильтр масштабирования «Область» у вебки на всех трёх сценах — при уменьшении
  билинейный по умолчанию заметно мылит.
- Фильтр «Увеличение резкости» 0.08 перед маской.
- У источников алертов включено «Управление звуком через OBS»: появились отдельные
  ползунки в микшере, громкость алертов больше не привязана к системному звуку.
